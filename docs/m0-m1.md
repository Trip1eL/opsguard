# M0 + M1 完成说明

## M0 工程基线

- `opsguard` Conda 环境使用 Python 3.11。
- `AppSettings.from_env()` 从进程环境和项目根目录 `.env` 加载非敏感运行配置，进程环境优先；API Key 不进入设置对象，也不会被日志打印。
- `configure_logging()` 提供统一日志初始化入口，业务模块通过 `get_logger()` 获取 logger。
- Pytest 和 Ruff 已加入开发依赖，当前测试命令如下：

```powershell
$env:PYTEST_DISABLE_PLUGIN_AUTOLOAD="1"
python -m pytest -q
ruff check src tests
```

禁用 Pytest 自动加载是为了隔离用户级安装的第三方插件；项目自身测试不依赖这些插件。

## M1 事件模型与数据集

`DatasetRecord` 将评估标签与生产事件分离：

```text
DatasetRecord
├── case_id / scenario
├── event_label / expected_stages  # ground truth
└── event: Event                   # 标准化事件 + raw_log
```

当前 fixture 包含：

- `suspicious_ssh_persistence`：异常 SSH 登录、外部脚本下载、计划任务持久化；
- `web_unusual_child_process`：Web 上传、Web 进程拉起 Shell、异常外联；
- `normal_release_window`：带变更单的证书登录、Ansible 发布和健康检查。

每条事件都具备唯一 `event_id`、UTC 时间戳、数据源、实体字段、标准化 action 和原始日志，后续 M2 parser/repository 可以据此实现查询和回溯。
