# M7：检测策略生成与离线沙箱验证

## 处理链路

```text
BehaviorChain + ATT&CK mappings
  -> SigmaRuleGenerator
  -> DetectionRule(DRAFT, versioned)
  -> SigmaRuleValidator
  -> CompiledSigmaRule
  -> OfflineRuleSandbox replay
  -> RuleValidationReport
  -> VALIDATED candidate or DRAFT candidate with adjustment suggestions
```

M7 在 M6 的调查链末端新增两个白名单工具：

- `generate_detection_rules`：Detection Engineering Agent 生成 Sigma 候选规则；
- `validate_detection_rules`：Validation Agent 在标注 fixture 上离线回放。

## 规则生成

`SigmaRuleGenerator` 根据行为链中有证据的 ATT&CK 映射生成稳定规则。相同技术集合
复用同一个 UUID 规则标识，通过 `DetectionRule.version` 形成新版本。当前受支持的
技术包括：

- `T1021.004`：新来源密码 SSH 登录；
- `T1053.003`：执行临时目录脚本的计划任务；
- `T1059.004`：Shell 或脚本解释器启动；
- `T1105`：curl/wget 工具传输；
- `T1505.003`：Web 服务进程拉起解释器；
- `T1071.001`：HTTP/HTTPS 应用层连接。

生成内容包含标准 Sigma 元数据、`logsource`、命名 selection、condition、ATT&CK
tags，以及用于审计的行为链、证据事件和规则版本。

## 安全执行边界

Sigma 使用 `yaml.safe_load` 解析，不通过字符串拆分或动态执行规则内容。验证器只
接受以下受限子集：

- 条件仅允许 `1 of selection_*`；
- 字段仅允许标准事件字段和 `attributes.*`；
- 修饰符仅允许 `contains`、`startswith` 和 `endswith`；
- 比较值仅允许字符串、数字和布尔值及其列表；
- Sigma ID 必须与领域模型中的规则 ID 一致。

`OfflineRuleSandbox` 将校验后的 selection 编译成内存谓词，对 Pydantic 事件逐条
比较。它不调用 Shell、不使用 `eval`、不访问网络、不写文件，也不执行 Sigma
内容中的任意指令。这里的沙箱是受限语言执行边界，不声称提供容器或虚拟机隔离。

## 验证范围与指标

一条规则面向一条行为链，因此回放数据由“该链上的可疑事件 + 全部正常事件”构成；
其他攻击场景不会被错误计为当前规则的漏报。报告包含：

- TP、FP、FN、TN；
- Precision、Recall、F1；
- False Positive Rate；
- 执行延迟；
- 命中事件；
- 误报和漏报的事件、案例及场景；
- 基于失败类型生成的规则调整建议。

默认通过阈值为 Precision >= 0.90、Recall >= 0.80、误报率 <= 0.05、回放延迟
<= 100ms。全部阈值可通过 `ValidationThresholds` 注入。

验证通过时只返回状态为 `VALIDATED` 的候选规则副本，原始 `DRAFT` 不被原地
修改。验证失败时规则保持 `DRAFT`。灰度、正式发布、人工审批和自动回滚由 M8
负责，M7 不产生任何生产环境副作用。
