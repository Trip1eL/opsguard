# M13：真实 Agent 编排与基础设施适配

## 目标

M13 把技术栈中的 LangGraph、OpenSearch、Neo4j 和 Docker 容器沙箱落到可调用的代码
边界，同时不牺牲个人项目的可重复启动能力。

## LangGraph

`LangGraphInvestigationOrchestrator` 为每个专项 Agent 角色注册一个图节点，节点之间
按 `DEFAULT_STEPS` 的依赖顺序连接，并在失败时路由到统一 finalize 节点。节点内部复用
已有 `ToolRegistry`、重试、错误分类和审计记录。`OpsGuardService` 默认使用该编排器，
仍可通过 `use_langgraph=False` 运行原显式 Orchestrator 做对照测试。

## OpenSearch

`OpenSearchEventRepository` 实现 `EventRepository` 协议，提供：

- 显式 index mapping：keyword、date、ip、object 和不可索引的 raw log；
- 单条与 bulk 写入，使用 `event_id` 作为文档 ID；
- 结构化 term、terms、range 查询和稳定时间排序；
- `from_url()` 工厂，支持 HTTP(S)、可选认证和 TLS 校验；
- 索引不存在时自动创建，bulk 错误转换为 `RepositoryError`。

服务通过 `OPSGUARD_EVENT_BACKEND=opensearch` 切换；设置
`OPSGUARD_OPENSEARCH_SEED_FIXTURES=true` 可在本地适配器演示中写入 fixture。

## Neo4j

`Neo4jBehaviorGraphAdapter.from_uri()` 使用官方 Neo4j Driver 建立连接，
`BehaviorCorrelator(graph_store=...)` 在生成 `BehaviorGraph` 后执行 upsert；关联分析
逻辑与图存储解耦，查询可使用 `related()` 获取实体邻居。服务通过
`OPSGUARD_GRAPH_BACKEND=neo4j` 切换，并支持可选的启动连通性验证。

## Docker 容器级规则沙箱

`DockerRuleSandbox` 将规则、标注事件和验证参数写入临时工作目录，启动只读、无网络、
丢弃 Linux capabilities、禁止新增特权、限制 PID/CPU/内存和超时的 worker 容器；容器
内部只调用受限的 `OfflineRuleSandbox`，不会执行规则内容中的 Shell 或网络操作。
worker 只返回 `RuleValidationReport`，上层继续使用原有精度、召回率、F1 和误报率门禁。

没有 Docker daemon 时，服务默认使用进程内回放；显式选择 `docker` 后，容器不可用会
返回脱敏的 `DockerSandboxError`，不会静默当作验证通过。

## 配置示例

```dotenv
OPSGUARD_EVENT_BACKEND=opensearch
OPENSEARCH_URL=http://localhost:9200
OPENSEARCH_INDEX=opsguard-events
OPSGUARD_GRAPH_BACKEND=neo4j
NEO4J_URI=bolt://localhost:7687
NEO4J_USER=neo4j
NEO4J_PASSWORD=change-me
OPSGUARD_RULE_SANDBOX=docker
OPSGUARD_SANDBOX_IMAGE=opsguard:latest
```

本地无外部服务时不设置这些变量即可使用 JSONL、内存图和离线沙箱。Compose 的
`adapters` profile 提供 OpenSearch 与 Neo4j 服务；API 默认仍保持本地模式，避免
普通测试和页面刷新隐式连接或写入外部服务。

## 验证边界

Fake Client/Driver 测试验证索引 mapping、查询 DSL、Neo4j driver 工厂、图 upsert 调用、
LangGraph 全链路和 Docker 隔离参数。当前开发环境 Docker daemon 未运行，因此未在本机
完成实际容器 build/run；Compose 配置和 worker 入口已通过静态检查。开启 Docker Desktop
后可按上述配置进行一次真实容器 smoke test。
