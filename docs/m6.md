# M6：Multi-Agent 调查编排

## 调查链路

`InvestigationOrchestrator` 使用显式、可审计的状态机依次调度五个专项角色：

```text
自然语言调查问题
  -> Investigation Agent / search_events
  -> Detection Agent / detect_anomalies
  -> Correlation Agent / correlate_behavior
  -> ATT&CK Mapping Agent / map_attack_techniques
  -> Evaluation Agent / get_detection_coverage
  -> InvestigationReport
```

`InvestigationToolbox` 将 M2-M5 的真实确定性服务封装为工具。自然语言中的
SSH、Web 子进程和计划任务关键词用于聚焦相关告警；时间、主机、用户、进程、IP、
域名和事件类型等精确条件通过 `InvestigationRequest.parameters` 传递给
`EventQuery`。

## 控制边界

- Agent 只能调用 `ToolRegistry` 中显式注册的工具；
- 每个工具都有结构化输入输出，领域模型在边界处转换为 JSON 兼容对象；
- 每次调用记录角色、工具、输入、输出、时间、尝试次数和失败类别；
- 超时和运行时错误可以重试，白名单拒绝、空结果和输出错误立即停止；
- 关键步骤失败后不继续调用依赖其结果的下游工具；
- 当前流程只读取 fixture 并执行确定性分析，不包含外部副作用。

失败类别包括 `not_allowed`、`empty_result`、`invalid_output`、`timeout` 和
`execution`。报告状态为 `completed`、`partial` 或 `failed`。

## 使用方式

```python
toolbox = InvestigationToolbox(
    repository,
    AttackTechniqueMapper(catalog),
    validation_records=records,
)
orchestrator = InvestigationOrchestrator(toolbox.registry())
report = orchestrator.run(
    InvestigationRequest(
        "调查新来源 SSH 登录后的可疑行为",
        parameters={
            "requested_technique_ids": [
                "T1021.004",
                "T1053.003",
                "T1105",
            ]
        },
    )
)
```

输出报告包含检索事件、告警、行为链与实体图、ATT&CK 技术映射、覆盖率、摘要和
完整工具 trace，可通过 `report.to_dict()` 序列化。

## 后续扩展

模型规划器或 LangGraph 可以接在 `InvestigationRequest` 与 `ToolRegistry` 之间，
但不得绕过现有工具白名单、结构化输出和失败分类。M7 已在调查链末端接入规则生成和
离线沙箱验证；响应审批和策略生命周期由 M8 接入。现有 `contracts.py` 和
`workflow.py` 保留了相应协议与状态控制点。
