# M9：反馈飞轮、API 与安全运营工作台

## 完整闭环

```text
调查问题
  -> 白名单 Multi-Agent 工具链
  -> 多源事件 / 告警 / 行为图 / ATT&CK 映射
  -> Sigma 候选 / 离线沙箱指标
  -> 独立人工审批
  -> 灰度评估 / 激活或回滚
  -> 分析员反馈
  -> 新候选版本 / 新旧版本离线对比
```

M9 为 M0-M8 的确定性核心增加可演示的应用边界。页面可以完成一次完整调查，
查看证据链和行为图，审批或拒绝响应，提交事件级反馈，并生成经过约束解析与离线
回放的新规则候选。反馈不会直接修改线上规则，也不会绕过新的审批周期。

## 反馈记录与版本隔离

`FeedbackRecord` 记录调查 ID、规则 ID、规则版本、事件 ID、反馈类型、分析员、
说明和带时区时间。当前 `InMemoryFeedbackStore` 是追加式本地适配器：

- 同一反馈 ID 重复写入相同内容时保持幂等；
- 同一反馈 ID 对应不同内容时拒绝冲突；
- 优化时只读取与当前 `rule_id + version` 完全匹配的反馈；
- 对外返回深拷贝，调用方不能修改已存记录。

反馈类型包括真阳性、误报和漏报。真阳性用于确认，不会因为一次确认就自动推荐
新规则；误报和漏报会进入受控候选生成流程。

## 候选规则优化

`RuleCandidateOptimizer` 不执行任意模型代码或字符串表达式，而是解析受限的
Sigma YAML 子集并修改结构化 detection AST：

- 误报反馈生成 `filter_feedback_*` 条件，优先使用变更单标记等可解释字段；
- 漏报反馈生成精确的 `selection_feedback_*` 条件；
- 规则 ID 保持不变，版本号加一，生命周期重置为 `DRAFT`；
- 候选内容再次通过字段白名单、修饰符白名单、条件语法和大小限制校验。

原规则与候选规则随后在同一固定数据集和同一目标事件集合上回放，对比 Precision、
Recall、F1 和误报率。只有沙箱验证通过、F1 提升且误报率不恶化时，
`recommended` 才为 true。该值只是“建议进入新审批周期”，不会发布、灰度或激活规则。

## FastAPI 接口

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/` | 返回安全运营工作台 |
| GET | `/api/health` | 健康检查 |
| GET | `/api/events` | 返回可标注的 fixture 事件 |
| POST | `/api/investigations` | 发起白名单参数调查 |
| GET | `/api/investigations/{id}` | 获取已保存调查 |
| POST | `/api/investigations/{id}/decision` | 提交人工审批与可选灰度指标 |
| POST | `/api/investigations/{id}/feedback` | 写入事件级分析反馈 |
| POST | `/api/investigations/{id}/evolve` | 生成并离线验证候选版本 |
| GET | `/api/feedback` | 查看当前进程中的反馈记录 |

普通调查参数使用显式 allowlist，并明确排除 `approval`。审批只能通过独立 decision
endpoint 进入服务层，避免 Agent 或自然语言参数把自身声明为已获批准。未知调查返回
404，非法参数、事件或演进前置条件返回 400。服务层只接受处于
`awaiting_approval` 状态的首次决策，已拒绝、激活、回滚或验证失败的调查均不能
重放审批。

## 工作台

工作台提供调查队列、事件与告警指标、行为时间线、ATT&CK 技术与置信度、行为阶段和
实体关系图、Sigma 内容、沙箱指标、风险处置建议、人工批准/拒绝、灰度指标、审计流、
反馈表单及规则版本对比。布局在桌面与移动视口下响应式重排，Sigma 和宽表在自身区域
滚动，不改变安全治理状态。

## 运行

```powershell
conda run -n opsguard python -m uvicorn opsguard.web.app:app --host 127.0.0.1 --port 8000
```

也可仅启动默认 Compose API 服务：

```powershell
docker compose up --build api
```

外部基础设施保留为可选 adapter profile：

```powershell
docker compose --profile adapters up --build
```

## 原型边界

- 调查、反馈、审批和模拟响应状态只保存在当前进程内，重启后清空；
- API 尚未接入生产认证、授权、租户隔离、CSRF 和速率限制；
- `ApprovalDecision` 是结构化原型对象，不是数字签名或生产授权凭证；
- 响应动作只修改内存沙箱，不会隔离真实主机、禁用账号或修改网络策略；
- 数据来自版本化 fixtures，数据库、事件流、外部日志平台和真实模型均位于 adapter 边界；
- Neo4j adapter 已定义，但当前行为图由内存图实现，不依赖运行中的 Neo4j。

因此该工作台适合本地演示、面试讲解与确定性回归，不应直接暴露到公网或接入生产处置。
